# Test strategy and production acceptance

## Reproducible local checks

`make check` runs Terraform formatting, Helm lint, Python lint/format, Go vet/race tests, debug-grant boundary/ownership tests, Helm safety invariants, strict Kubernetes native schemas, and custom-resource validation against the exact pinned CRDs. Kubernetes schema checks intentionally skip CRs; the separate Python validator must cover every application CR kind. Upstream YAML merge expansion is explicit in `bootstrap_crds.py`.

`make terraform-init terraform-test` uses mocked AWS provider data and plan-only Terraform tests. The tests verify three AZs/NAT/node groups, private EKS, protected encrypted data, S3 gateway routing, and reject two-AZ, mixed-region, missing-tag, and undersized-node inputs. They do not validate account quotas, AMI availability, real IAM evaluation, or actual resource creation.

The same target checks the existing-cluster root and shared data-services module: role reuse must create no IAM roles/policies, externally owned associations must remain unmanaged, and existing subnet/VPC/AZ coordinates must be preserved. Installer tests feed synthetic inventories into read-only preflight and use real Helm rendering to verify controller exclusion, existing storage propagation, ownership checks, context identity, secret preservation and stale-overlay rejection. The deployment command must never run after failed preflight or with `--check-only`.

`make runtime-test` executes all three Vector and five OTel collector configurations with the real pinned images, verifies Tempo configuration, and validates Mimir configuration for its nine distributed targets. Vector additionally executes actual transforms for ordinary errors, default-denied debug/trace, valid grants, expiry, malformed/overlong/future grants, identity spoofing, and removal of grant fields. Go tests use a real temporary Valkey instance to verify concurrent independent admission instances share one error budget, other services remain independent, and debug/byte sub-budgets work. HTTP tests cover unavailable quota state, malformed identity/JSON, oversized batches, concurrency saturation, and completion of an in-flight request during shutdown.

`make image integration-test` builds the quota image and runs a complete isolated log path: a substituted local Vector HTTP source feeds the production identity/normalization/grant/throttle transforms, the quota service, a Vector gateway, Kafka, a Vector consumer, and ClickHouse/Keeper. It asserts stored flood/error counts, an unaffected quiet service, one permitted debug event, no expired debug event, and the derived aggregate count. This uses one broker/database/Keeper and does not model AZ failure. Test resources are removed in a `finally` block.

`make sharding-test` starts real ClickHouse servers with two shards and three replicas each, verifies distribution and cross-shard queries, stops a replica, expands to three shards, rejects a legacy local-table schema, and stops an entire shard to check fail-closed reads/writes. It uses one local Keeper and does not execute the Altinity operator or Helm schema hook.

`make consumer-test` uses 36 Kafka partitions, the production Vector consumer configuration and two ClickHouse shards with one replica each. It verifies a 12,000-record backlog, consumer-group resizing from one to three to two, complete partition ownership, offsets held during a paused ClickHouse outage, and 22,800 stored event identities and derived counts. Replicas are changed explicitly through Docker; this does not execute KEDA/HPA reconciliation.

The optional Flink chart/CR can be rendered and schema-validated using a dummy job image for validation. A real job must supply separate job/connector tests. Readiness and schema checks are not substitutes for a live traffic test.

`make collector-test` runs real Arrow agent/gateway links, a trace-ID router and three production tail samplers. It tests unsafe metric attributes, missing writer identity, excessive labels, preserved independent writers, visible filter-drop counters, and 48 traces whose two batches must land on the same sampler. Only discovery/endpoints and backend file sinks are substituted. It does not establish Mimir/Tempo storage integration or throughput.

`make rules-test` uses pinned Prometheus tooling to validate all provisioned rule syntax and evaluate healthy/overload fixtures. Dashboard/query artifacts, mounted rule sources, Flux schemas, controller ownership, revision tracking, and narrowly scoped drift exceptions are part of `make check`. CI renders every checked-in regional release. Actual Flux reconciliation and Grafana file reload still require a cluster.

`make red-test` exercises two real span-metric producers through Arrow and the gateway's remote-write exporter into Prometheus, with production trace routing and three tail samplers. It verifies counts, error normalization, histogram units, independent writers, excluded span kinds, original-span preservation and bounded route cardinality. Prometheus substitutes for Mimir storage. `make dashboard-test` uses the pinned Grafana image to check provisioning and file reload; it does not assert browser layout or live Tempo/ClickHouse queries.

## Required acceptance in a disposable AWS environment

Do not label the platform production-validated until these tests run on the intended versions and topology, with evidence retained:

1. Provision each region from its own state and generated coordinates. Validate EKS access, Pod Identity credentials, encrypted EBS, S3 policies, RDS/Valkey authentication, autoscaler scale-up, pod placement across physical AZs, and network policy enforcement.
2. Deploy a JSON log canary with the platform service label. Send a sustained noisy service next to a quiet service. Measure admitted/dropped events and bytes against `burst + rate × time`, before/during/after HPA and blue-green. Confirm no severity bypass, no pod-label identity forgery, and no direct application access to Kafka/ClickHouse/quota backends.
3. Grant debug for a short test duration. Verify logs arrive while valid, stop at expiry with the controller disabled, and resume only after a new explicit grant. Test new pods during a grant, revoked grants, unauthorized annotation edits, and clock skew.
4. Onboard a real instrumented service and compare RED against direct request counters, verify missing data is distinct from zero errors, exercise overflow and check Grafana filters/retained traces. Then emit a known OTLP counter with unique writer identity and trace from a canary, query Mimir/Tempo and Grafana, and verify cross-signal `service.name`/`trace_id` correlation. Verify a single assigned scrape per target, bounded series/sample limits, and late-span/sampling behavior.
5. Stop one Kafka broker/Keeper/ClickHouse replica at a time and verify quorum, durability, readable data, and recovery. Then exercise an AZ outage in an isolated test environment. PDBs govern voluntary evictions; they do not guarantee involuntary failures are harmless. Test EBS attachment constraints after AZ loss.
6. Promote each stateless tier during traffic; prove old/new connections drain, Kafka consumer offsets commit, error/drop counters stay within expectations, and rollback restores the old image. Tail-sampler tests must quantify incomplete/lost traces during replacement rather than assume zero loss.
7. Exercise a controlled Valkey failover and network timeout. Confirm 503/backpressure, bounded burst overshoot from stale replicated state, queue recovery, and admitted duplicate/loss semantics. Fill a bounded buffer in a disposable node to measure rotation loss.
8. Commit a pipeline, dashboard, query and rule change. Verify Flux revision adoption, automatic/manual promotion as configured, Grafana/Mimir content reload, and correction of an intentional manual drift. Verify HPA and Argo selector updates are not reverted.
9. Induce Kafka consumer lag. Verify KEDA scales the writer Deployment within its ceiling, workers acquire partitions, pending pods trigger node scaling, and lag falls without overloading ClickHouse. Exercise scaler metric failures, the explicit CPU fallback, gradual scale-down and zero-replica maintenance pause. Expand ClickHouse through pause/expand/resume PRs and prove that every node has the new topology/schema before writers resume. Verify the Helm hook fails on a legacy schema.
10. Restore snapshots/PVCs/object data and restore a region. State the measured RPO/RTO and costs. Cross-region raw replication is absent, so a surviving region cannot magically reconstruct the failed region's history.

Capture manifests, immutable image IDs, timings, query results, queue/drop metrics, and cost/throughput measurements. Record failures as failures. Do not weaken quotas or skip unavailable replicas just to make an acceptance run pass.

## Studio, catalog and eBPF additions

Run `make studio-test service-test profiling-test rules-test dashboard-test`. Studio compiler tests cover both provisioning paths, scope/ownership rejection, unsafe inputs, ZIP CRC/content round trips, and validation of exported contracts by the real Python validators. `make studio-terraform-test` initializes/validates a generated Terraform root with no apply. Catalog tests cover schema failures, duplicate identity, escaping, stale generated content, safe scaffolding, invalid Helm inputs and publish confirmation. The Go starter tests health/accounting and propagated server spans with bounded route labels. Promtool exercises generated multi-window SLO burn, healthy and idle cases. The actual Grafana binary provisions the catalog and RED dashboards and reloads file changes.

`make profiling-test` validates rendered optional native objects, Alloy positive/negative configurations, Hubble scrape configuration, and Pyroscope v2 YAML/metastore flags using its API target. This deliberately does not attach eBPF probes or exercise distributed Pyroscope storage. Live Cilium enforcement, workload endpoint coverage, kernel profile capture, S3/Pod Identity, Raft restore, profile ingestion/query and AZ loss remain the qualification gates in `ebpf.md`. The separate Cilium reference chart is locked and can be rendered/validated without installing it.

For browser acceptance, test the environment/capacity/visibility/review steps, both cluster modes, configuration ZIP, service definition export, private catalog import/search, validation errors and narrow/mobile layout. The static builder must never include actual catalog or environment data. Hosted Pages and notification delivery need separate live checks.

## Support regression and acceptance

Run `make support-test` for exact stored log/metric/trace checks using real local backends, Mimir tenant configuration and local owner/default alert delivery, backend scraping through Arrow/remote write, dashboard query execution and pinned Kafka exporter lag/replication metrics. `make rules-test` covers failed, missing, stalled and healthy support checks plus sustained Kafka backlog/replication failures. Unit tests cover stale/wrong identities, partial ingestion, receiver validation, safe support projection and owner-scoped debug requests. No cloud calls or real pages are part of these tests.

The local support fixture starts the pinned support runtime without credentials when checks are disabled, and tests the rendered canary profile against native ClickHouse: bounded reads succeed, writes and scan-limit overrides fail. It uses Prometheus in place of Mimir metrics storage, single-node Tempo/ClickHouse, synthetic Kubernetes log metadata, and a direct Vector storage sink. Existing integration/consumer/sharding suites separately cover Kafka and replicated storage. The trace fixture bypasses tail routing; `collector-test` checks trace affinity and sampling. Qualify the full deployed canary, independent health polling, actual alert receivers/resolution, credential rotation, private networking and failure/recovery on EKS before production. The scrape test checks actual retained samples, not merely `up=1`.
