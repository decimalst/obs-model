# What remains for telemetry in a box

The repository provisions and configures a regional telemetry platform, including protected log admission, trace sampling, metric cardinality controls, sharded log storage, lag-based consumers, Git-managed content and service RED metrics. It still needs environment qualification and a fuller day-to-day service experience. The table distinguishes shipped behavior from proposed work; these are not enabled features.

| Priority | Capability | Current state and concrete next step |
|---|---|---|
| Delivered in 0.4 | Common service RED | Pre-tail span metrics, request/error/duration dashboard, region/cluster/service filters, recording rules, overflow alert and SDK onboarding fragment. Qualify with actual applications; observed spans are not guaranteed request counts. |
| Before production | Live deployment qualification | Run the documented EKS/IAM/network-policy, scaling, AZ-loss, promotion, restore and regional-recovery gates. Retain evidence and capacity measurements; local containers do not prove these. |
| Before production | Identity and secure intake | Administrative namespace trust and referenced secrets exist. Add the deployment's SSO/RBAC, ingress TLS, authenticated telemetry identity, tenant authorization and auditable policy ownership. Internal plaintext transport is a material remaining gap. |
| Before production | Sensitive-data policy | Arbitrary fields are excluded from generated metric labels, but trace attributes and log message bodies can still contain sensitive data. Add reviewed redaction/drop rules, representative fixtures and retention ownership before accepting such data. |
| Before production | Service ownership and alert delivery | Mimir evaluates Git-managed rules; no real receiver or paging route is invented. Provide team/service metadata, severity conventions, runbook links, notification credentials and a tested delivery path. |
| Next usability increment | Instrumentation onboarding | Supply language-specific quickstarts, opt-in automatic instrumentation recipes, context/log correlation and a canary that proves all three signals end to end. The existing operator and env fragment do not instrument arbitrary applications. |
| Next usability increment | Service dependency graphs | Add bounded client/server span pairing on a trace-affine tier before tail sampling. Pairing at independent node agents can miss cross-node edges. Measure orphan/expired edges and distinguish inferred external peers from directly observed services. |
| Next usability increment | SLOs and error budgets | Provide versioned service definitions, numerator/denominator contracts, multi-window burn alerts and an overview dashboard. Prefer direct application metrics where SDK sampling or collector loss makes span metrics unsuitable. Avoid a single generic latency/error threshold for every service. |
| Next usability increment | Platform capacity dashboards | Extend basic health charts with Kafka lag/age and ISR, ClickHouse shard/quorum/insert performance, Mimir rejection/query limits, Tempo ingestion, collector queues and drop counters. Wire the required exporters and test every metric/query; do not ship empty panels pointing at absent metrics. |
| Next operations increment | Quota and debug self-service | Add a reviewed service-onboarding interface, ownership checks, previewed budget/cost changes, expiring debug requests and audit history. Keep runtime expiry enforcement independent of cleanup. |
| Next operations increment | Recovery and upgrade automation | Turn restore and upgrade runbooks into rehearsable jobs with fixtures, compatibility gates and documented roll-forward paths. Reconcile schema migrations explicitly; Git rollback cannot reverse durable data changes. |
| Later, driven by demand | Stronger tenancy and regional discovery | Support authenticated shared-cluster intake and federated datasource/service discovery while retaining regional raw data. The current independent cells and `cluster_name` fields are not hostile-tenant isolation or transparent regional failover. |

The recommended next product increment is a service onboarding contract connecting instrumentation, owner, dashboard, SLO, quota, retention and alert route. It provides a consistent workflow without hiding the underlying operational controls. Service graphs then add useful navigation on top of trustworthy identity and complete trace routing.
