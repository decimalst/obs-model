# What remains for telemetry in a box

The repository provisions and configures a regional telemetry platform, including protected log admission, trace sampling, metric cardinality controls, sharded log storage, lag-based consumers, Git-managed content and service RED metrics. It still needs environment qualification and a fuller day-to-day service experience. The table distinguishes shipped behavior from proposed work; delivered increments are marked explicitly; the remaining rows are not enabled features.

| Priority | Capability | Current state and concrete next step |
|---|---|---|
| Delivered in 0.4 | Common service RED | Pre-tail span metrics, request/error/duration dashboard, region/cluster/service filters, recording rules, overflow alert and SDK onboarding fragment. Qualify with actual applications; observed spans are not guaranteed request counts. |
| Before production | Live deployment qualification | Run the documented EKS/IAM/network-policy, scaling, AZ-loss, promotion, restore and regional-recovery gates. Retain evidence and capacity measurements; local containers do not prove these. |
| Before production | Identity and secure intake | Administrative namespace trust and referenced secrets exist. Add the deployment's SSO/RBAC, ingress TLS, authenticated telemetry identity, tenant authorization and auditable policy ownership. Internal plaintext transport is a material remaining gap. |
| Before production | Sensitive-data policy | Arbitrary fields are excluded from generated metric labels, but trace attributes and log message bodies can still contain sensitive data. Add reviewed redaction/drop rules, representative fixtures and retention ownership before accepting such data. |
| Delivered in 0.6 / before production | Ownership and alert delivery | Owner/default webhook routing is reconciled from Git and existing Secrets, with explicit tenant ownership and native local delivery tests. Actual receiver credentials, transport hardening and external delivery acceptance remain environment-specific. |
| Delivered in 0.5 / next | Instrumentation onboarding | Go service scaffolds now include direct request counters, W3C/OTLP tracing, correlated JSON logs, CI and Helm. Existing-app registration preserves ownership. The 0.6 opt-in canary verifies exact stored logs, metrics and traces. More language recipes, profile probes and actual EKS acceptance remain. |
| Next usability increment | Service dependency graphs | Add bounded client/server span pairing on a trace-affine tier before tail sampling. Pairing at independent node agents can miss cross-node edges. Measure orphan/expired edges and distinguish inferred external peers from directly observed services. |
| Delivered in 0.5 / next | SLOs and error budgets | Optional per-service availability definitions, explicit metric contracts and tested multi-window burn alerts are generated from Git. Durable compliance reports, latency objectives, delivery verification and missing-telemetry alerts remain. |
| Delivered in 0.6 / next | Platform capacity dashboards | Verified backend scrapes, Kafka lag/under-replication, ClickHouse physical inserts/readonly replicas/replication queues, collector retry queues, Tempo ingress, alert attempts and stored-signal health. Queue age, per-shard disk forecasts and fuller Mimir rejection/query-limit coverage remain. |
| Delivered in 0.6 / next | Quota and debug self-service | Protected workflow checks catalog ownership, exact actor/environment scope and workload identity; emits request audit records and preserves runtime expiry. Quota/cost previews, a multi-user portal and durable audit retention remain. |
| Next operations increment | Recovery and upgrade automation | Turn restore and upgrade runbooks into rehearsable jobs with fixtures, compatibility gates and documented roll-forward paths. Reconcile schema migrations explicitly; Git rollback cannot reverse durable data changes. |
| Later, driven by demand | Stronger tenancy and regional discovery | Support authenticated shared-cluster intake and federated datasource/service discovery while retaining regional raw data. The current independent cells and `cluster_name` fields are not hostile-tenant isolation or transparent regional failover. |

The 0.5 increment adds an offline deployment studio, service catalog/scaffolding, ownership metadata, optional availability SLOs, Hubble metrics/UI integration and regional CPU profiling. The 0.6 support increment adds scoped debug workflow authorization, configurable alert routing, a three-signal canary, capacity views and a local support inventory. Strong runtime identity, transport hardening, application dependency graphs and live restore/HA qualification remain explicit gaps. Hubble packet maps do not replace a trace-derived service graph.
