# What remains for telemetry in a box

The repository provisions and configures a regional telemetry platform, including protected log admission, trace sampling, metric cardinality controls, sharded log storage, lag-based consumers, Git-managed content and service RED metrics. It still needs environment qualification and a fuller day-to-day service experience. The table distinguishes shipped behavior from proposed work; delivered increments are marked explicitly; the remaining rows are not enabled features.

| Priority | Capability | Current state and concrete next step |
|---|---|---|
| Delivered in 0.4 | Common service RED | Pre-tail span metrics, request/error/duration dashboard, region/cluster/service filters, recording rules, overflow alert and SDK onboarding fragment. Qualify with actual applications; observed spans are not guaranteed request counts. |
| Partial live evidence / further qualification | Live deployment qualification | One offline 26-gate batch and append-only operator evidence ledger cover deployment, security, scaling, AZ loss and recovery. The [September 25 AWS lab](validation.md#2026-09-25-authorized-disposable-aws-deployment) exercised deployment, stored signals, bounded log isolation, a narrow IAM probe and complete teardown. It did not complete the formal batch; HA/DR/security acceptance and a new cold start with the later startup guards remain pending. |
| Delivered in 0.7 / before production | Identity and secure intake | Existing-secret Grafana OAuth/OIDC, TLS ingress/external proxy profiles, strict group roles and Grafana-scoped external mesh examples are generated and locally tested. Full internal TLS, authenticated telemetry identity and tenant authorization remain per-hop integration work; setup alternatives are explicit. |
| Delivered in 0.7 / owner setup | Sensitive-data policy | Opt-in log redaction/drop presets and trace attribute allowlisting have native positive/negative fixtures. Owners must review permitted fields and losses, extend application-specific coverage and handle historic/raw/profile data separately; this is not comprehensive PII detection. |
| Delivered in 0.6 / before production | Ownership and alert delivery | Owner/default webhook routing is reconciled from Git and existing Secrets, with explicit tenant ownership and native local delivery tests. Actual receiver credentials, transport hardening and external delivery acceptance remain environment-specific. |
| Delivered in 0.5 / next | Instrumentation onboarding | Go service scaffolds include direct request counters, W3C/OTLP tracing, correlated JSON logs, CI and Helm. Existing-app registration preserves ownership. The opt-in canary verified exact stored logs, metrics and traces in the AWS lab. More language recipes, profile probes and acceptance of real instrumented applications remain. |
| Delivered in 0.7 / opt-in | Service dependency graphs | Client/server spans pair before tail sampling on the trace-affine sampler tier, with a finite service-name allowlist, bounded pairing cache and independent writers. Native tests prove graph metrics at zero tail retention. Uninstrumented peers/messaging inference and live Grafana map acceptance remain outside this mode. |
| Delivered in 0.5 / next | SLOs and error budgets | Optional per-service availability definitions, explicit metric contracts and tested multi-window burn alerts are generated from Git. Durable compliance reports, latency objectives, delivery verification and missing-telemetry alerts remain. |
| Delivered in 0.6 / next | Platform capacity dashboards | Verified backend scrapes, Kafka lag/under-replication, ClickHouse physical inserts/readonly replicas/replication queues, collector retry queues, Tempo ingress, alert attempts and stored-signal health. Queue age, per-shard disk forecasts and fuller Mimir rejection/query-limit coverage remain. |
| Delivered in 0.6 / next | Quota and debug self-service | Protected workflow checks catalog ownership, exact actor/environment scope and workload identity; emits request audit records and preserves runtime expiry. The 0.7 offline cell planner previews configured budget scopes and rejects accidental declared backend sharing. Dollar forecasts, a multi-user portal and durable audit retention remain. |
| Delivered in 0.7 / execution deferred | Recovery and upgrade automation | Offline plans, evidence validation, native/external backup setup and explicit isolated restore/roll-forward procedures are supplied. Backend restore execution and provider-specific jobs remain operator-owned and must be rehearsed in the deferred batch; Git rollback cannot reverse durable data changes. |
| Delivered options / further integration | Stronger tenancy and regional discovery | Shared-cell budgets and separate cluster/backend plans support different contention boundaries. Authenticated multi-tenant shared intake, shared per-service non-log quotas and federated discovery are still not generated. Declared isolation needs live IAM/network/load proof. |

The 0.5 increment adds an offline deployment studio, service catalog/scaffolding, ownership metadata, optional availability SLOs, Hubble metrics/UI integration and regional CPU profiling. The 0.6 support increment adds scoped debug workflow authorization, configurable alert routing, a three-signal canary, capacity views and a local support inventory. Strong runtime identity, complete transport hardening and live restore/HA qualification remain explicit gaps. Hubble packet maps do not replace a trace-derived service graph.

The 0.7 increment adds [setup choices](setup-options.md), [security profiles](security.md), [privacy and graphs](privacy-and-service-graphs.md), [cell budget/isolation review](isolation.md) and [one AWS qualification batch](live-qualification.md). Environment-specific values and ownership stay explicit. Ordinary local validation creates no cloud resources; the separately authorized, later AWS lab is recorded in the dated validation evidence.
