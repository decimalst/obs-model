# Finish configuration before the AWS rehearsal

Use this page to choose environment-specific integrations without blocking local development. The [qualification batch](live-qualification.md) is the single place to track live results. An example profile or a successful local render is never a completed AWS gate.

## Prepare an offline bundle

1. Generate a configuration with the studio, or start from `examples/existing-platform.yaml`. Choose new EKS, existing EKS with managed data services, or software-only ownership. Supply actual AZ names and explicit operator ownership when those are known; do not import existing resources to make an example work.
2. Choose a [security profile](security.md), [privacy and graph policy](privacy-and-service-graphs.md), support settings, and any dedicated [regional cells](isolation.md). Commit only nonsecret definitions. Keep endpoint URLs that contain credentials, passwords and certificates' private keys in your secret-management system.
3. Render without contacting AWS or Kubernetes:

   ```sh
   .venv/bin/python scripts/install.py \
     --config examples/existing-platform.yaml \
     --quota-image YOUR_REGISTRY/log-quota@sha256:YOUR_PUBLISHED_DIGEST \
     --security-profile examples/security-oidc-ingress.yaml \
     --tuning examples/tuning-privacy-graphs.yaml \
     --render-only --output-dir build/reviewed-install
   ```

   Replace the image placeholder with a real immutable digest. The command validates the nonsecret contract, produces Helm values, persists the selected profile and emits external security prerequisites. It calls local Helm only. External mesh policies are review examples and are not installed by Helm or Flux.
4. Run `make check terraform-test runtime-test privacy-graph-test security-test qualification-test` and the relevant existing pipeline suites. Prepare the deferred run using `operations/qualification.example.yaml`. Real account/cluster identities, source revision, backup ownership and RPO/RTO are completed before the live rehearsal, not invented now.
5. Later, in the live AWS batch, replace `--render-only` with `--check-only` to read real prerequisites. Removing both flags invokes the installer and changes the cluster. Terraform provisioning is a separate reviewed plan/apply step. There is no automatic transition from offline checks to deployment.

## Integration choices and owner actions

| Area | Supported configuration or extension path | Required setup and later evidence |
|---|---|---|
| Grafana identity | Local admin for loopback access; generic OAuth/OIDC for organization access | Existing server encryption-key Secret, existing admin Secret, or client-id/client-secret Secret; register exact callback and permitted groups. Verify wrong-group rejection and recovery access. SAML/auth-proxy can remain externally managed but are not generated by these profiles. |
| Browser TLS | Existing TLS ingress class/Secret; externally managed HTTPS proxy | Owner creates DNS/certificate and controls ingress. Set exact URL and proxy namespace. Validate TLS trust, forwarding, cookies and callback. No ingress controller is installed implicitly. |
| Internal transport/intake | Trusted cluster network; externally owned Istio/Linkerd policy examples; per-component native TLS setup | Review the hop-by-hop coverage matrix in `security.md`. The generated mesh example covers Grafana only. Node agents, Arrow/OTLP, Kafka, database peers and profiling require their own enrollment/certificate/authorization work before claiming full encryption. |
| Sensitive data | Logs off/redact/drop with selected reviewed patterns; traces off/attribute allowlist | Data owner chooses fixtures, safe attributes and retention. Strict trace mode intentionally loses events and linked spans. Query storage for synthetic secrets, not merely the collector response. Existing data is not retroactively scrubbed. |
| Service dependencies | Declared catalog dependencies; observed client/server graph connector | Explicit bounded service-name allowlist and consistent trace propagation. Names must be unique within the cell. Exercise partial traces, pairing expiry and sampler restarts. The graph is inferred from observed spans. |
| Non-log fairness | Shared tenant budgets; separate clusters/backends for critical teams | Review `cell_plan.py` output and isolate actual IAM/backend/node capacity where required. Authenticated multi-tenant admission with shared per-service budgets remains an additional integration, not a service-label setting. |
| Instrumentation | Generated Go service; existing SDK/manual instrumentation; externally managed auto-instrumentation | Apply namespace/service/writer identity and W3C propagation; use HTTP/protobuf or gRPC to node agents as appropriate. Keep SDK/version ownership with each application, disable duplicate instrumentation, and compare direct request counts to observed spans. CPU profiling is a separate explicit opt-in. |
| SLOs | Built-in availability burn rules from direct counters or observed spans; externally generated reviewed rules | Owner declares denominator and objective, configures alert receiver and tests no-traffic/zero-error/overload cases. Latency objectives and durable compliance reports are not produced by the current catalog compiler; use a separately owned SLO engine or reviewed rule generator, then commit its output to the existing file-provisioned rule path. Do not run two reconcilers against the same rule source. |
| Alert delivery | Existing external tenant configuration; Git-owned default/owner generic webhooks | Configure existing receiver Secret and explicit tenant handover. Slack/Teams-specific conversion needs a receiver adapter. Test firing and resolution later, with explicit approval to contact the real destination. |
| Support monitoring | Independent external polling; existing enterprise monitoring | Poll each support pod or provide an external probe that accounts for replicas. Mimir's own alerts cannot independently detect a complete Mimir outage. Record polling ownership and incident routing. |
| Catalog/debug self-service | PR and protected workflow; externally owned internal developer portal | Protect policy/workflow paths, bind actual GitHub actors to exact environments, configure operations role/private runner, and retain workflow audit logs. A portal may open reviewed PRs or invoke this workflow; it must authenticate callers and cannot treat a supplied actor string as identity. |
| Capacity/cost views | Included support/RED dashboards; organization-specific forecast/rate-card integration | Measure traffic, cardinality, queue growth, disk and replica overhead; use account-specific prices. Queue age, disk forecasts and fuller rejection panels need qualified metric contracts. Do not interpret a missing series as zero or estimate cost from replica counts alone. |
| Backups/upgrades | Native per-backend backups; externally managed backup service | Supply recovery owner, isolated target and approved RPO/RTO. Rehearse native or provider-specific restore and stateful roll-forward. Version control cannot reverse durable data migrations. |
| Regional continuity | Independent cells; separately approved replication/recovery | Preserve region-local raw data by default. Remote history requires explicit replication, KMS/IAM, offset mapping, measured lag and cost assessment. Multiple regions alone do not supply transparent failover. |

## Automate without changing ownership

For manual installations, keep the reviewed platform contract and generated values together and rerun read-only preflight immediately before deployment. For Flux, use `gitops_export.py --security-profile PROFILE` or the persisted `security_profile` in the platform contract; the same compiler feeds Helm values and drift reconciliation. Keep external certificate, IdP and mesh manifests in their existing owner's repository. Profile removal or change is an explicit migration—Git rollback alone does not recover encryption keys or stored alert configuration.

For CI, the included workflow tests locally without an AWS identity. Configure your own protected deployment environment and OIDC role for a later apply job, scoped to the exact account/state/cluster and reachable from a private runner. Do not reuse the application publication or debug-grant role for infrastructure administration. Choose automatic or manual stateless promotion; samplers and quorum stores retain their drain/migration procedures. Export sanitized qualification evidence to your approved audit store and review names/topology before sharing support inventories.
